# GenSPARQL workbench

The workbench of the demonstration. It shows the two graphs of the demonstration, both built from Wikidata: the World Cup 2026 graph (`worldcup2026.ttl`, 1,248 players of 48 teams) and the Nobel Prize graph (`nobel-prize.ttl`, 1,018 laureates). For GenSPARQL itself, the engine and the evaluation, see the [repository README](../README.md).

## Two modes

- **Recorded mode** (`index.html`, the project page). It needs no backend and no LLM. For each graph it replays three queries with the answers that three open-weight LLMs gave through the GenSPARQL service in the evaluation (`recorded-runs.js`, generated by `eval/www27/make_recorded_data.py`):
  - *Ground entities* maps generated names to entities with the Jaccard or the embedding similarity and the threshold θ;
  - *Generate attributes* compares generated values with Wikidata;
  - *Compose + defer* counts the LLM calls in the order of the planner and with GENOP evaluated first.
- **Live mode** (`index.html?mode=live`). The workbench sends each query unchanged to the GenSPARQL service, and the Java engine evaluates it. The result table shows the answers and the number of LLM calls. The sample queries follow the scenarios of the paper, and loading a sample selects the graph that it queries.

## Running the live mode on this machine

```bash
ollama pull mistral:7b      # the chat model of the demonstration
ollama pull bge-large       # the embedding model
./start-fuseki.sh           # from the repository root; serves the workbench at http://localhost:8080
```

Open `http://localhost:8080/?mode=live`. The live panel is preset to Ollama at `http://localhost:11434/v1` with `mistral:7b` and `bge-large`, and the API key field can stay empty. Any other OpenAI-compatible endpoint, such as a vLLM server or a hosted API, can be entered instead; its key is sent with each query and not stored.

The recorded mode also runs from a static server, for example `python3 -m http.server 8000` in this folder.

## Service API used by the workbench

- `GET /api/gensparql/health`
- `POST /api/gensparql/datasets` (multipart `file`): loads an RDF graph and returns its `datasetId`. The workbench uploads the built-in graph, or a Turtle file chosen with *Upload KG*, before the first query.
- `POST /api/gensparql/query` with `datasetId`, `query`, `includeTrace` and two optional objects:
  - `llm`: `apiKey`, `baseUrl`, `model`;
  - `similarity`: `method` (`jaccard` or `embedding`), `baseUrl`, `model`, `apiKey`.

  The endpoint, model and key apply to this query only. With `includeTrace`, the response reports the number of GENOP calls in `trace.genopCalls`.

## Files

- `index.html`, `styles.css`, `app.js`, `page-mode.js`: the page and its two modes. `index.html?print` lays out the workbench views in two columns for figures.
- `engine-client.js`: calls to the service (default `http://localhost:8080`).
- `native-graph.js`: the graph view. Its layout runs on d3-force from the local copy `vendor/d3.v7.8.5.min.js` (ISC license, `vendor/d3-LICENSE.txt`).
- `database-adapters.js`, `fifa2026-data.js`, `nobel-prize-data.js` and the two `.ttl` files: the built-in graphs.
- `demo-data.js`: the recorded queries and the live defaults.
- `recorded-runs.js`: the recorded answers.
- `video/`: the narrated demo video.
