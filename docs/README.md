# GenSPARQL workbench

The workbench of the demonstration. It shows the two graphs of the demonstration, both built from Wikidata: the World Cup 2026 graph (`worldcup2026.ttl`, 1,248 players of 48 teams) and the Nobel Prize graph (`nobel-prize.ttl`, 1,018 laureates). For GenSPARQL itself, the engine and the evaluation, see the [repository README](../README.md).

## Two modes

- **Recorded mode** (`index.html`, the project page). It needs no backend and no LLM. For each graph it replays three queries with the answers that three open-weight LLMs gave through the GenSPARQL service in the evaluation (`recorded-runs.js`, generated by `eval/www27/make_recorded_data.py`):
  - *Ground entities* maps generated names to entities with the Jaccard or the embedding similarity and the threshold θ;
  - *Generate attributes* compares generated values with Wikidata;
  - *Compose + defer* counts the LLM calls in the order of the planner and with GENOP evaluated first; *Play steps* shows the steps of an order one after the other.
- **Live mode** (`index.html?mode=live`). The workbench sends each query unchanged to the GenSPARQL service, and the Java engine evaluates it. The result table shows the answers and the number of LLM calls. The sample queries follow the scenarios of the paper, and loading a sample selects the graph that it queries. The page waits up to ten minutes for an answer, since a local model may need that long for a query with many prompts, and it remembers the endpoint and model names of live mode in the browser, never the key.

In both modes the Info panel beside the graph shows the details of a selected node, relation or result row, and while nothing is selected the settings of the view. The address keeps the graph, the scenario, θ and the similarity, so a link such as `index.html?db=nobelPrize&tab=composition` or `index.html?theta=0.70&sim=embedding` opens the same view.

## Running the live mode on this machine

```bash
ollama pull mistral:7b      # the chat model of the demonstration
ollama pull bge-large       # the embedding model
./start-fuseki.sh           # from the repository root; serves the workbench at http://localhost:8080
```

Open `http://localhost:8080/?mode=live`. Live mode is preset to Ollama at `http://localhost:11434/v1` with `mistral:7b` and `bge-large`, and the API key field can stay empty. Any other OpenAI-compatible endpoint, such as a vLLM server or a hosted API, can be entered instead; its key is sent with each query and not stored.

The recorded mode also runs from a static server, for example `python3 -m http.server 8000` in this folder.

## Service API used by the workbench

- `GET /api/gensparql/health`
- `POST /api/gensparql/datasets` (multipart `file`): loads an RDF graph and returns its `datasetId`. The workbench uploads the built-in graph, or a Turtle file chosen with *Upload KG*, before the first query.
- `POST /api/gensparql/query` with `datasetId`, `query`, `includeTrace` and two optional objects:
  - `llm`: `apiKey`, `baseUrl`, `model`;
  - `similarity`: `method` (`jaccard` or `embedding`), `baseUrl`, `model`, `apiKey`.

  The endpoint, model and key apply to this query only. With `includeTrace`, the response reports the number of GENOP calls in `trace.genopCalls`.

## Files

- `index.html`, `styles.css`, `app.js`, `page-mode.js`: the page and its two modes. `index.html?print` lays out the graph panel as a figure for a two-column paper.
- `engine-client.js`: calls to the service: by default the service that serves the page, or else `http://localhost:8080`.
- `explorer-info.js`: the Info panel beside the graph.
- `native-graph.js`: the graph view, drawn as SVG. Zoom and pan are d3-zoom, dragging a node is d3-drag and the layout runs on d3-force, all from the local copy `vendor/d3.v7.8.5.min.js` (ISC license, `vendor/d3-LICENSE.txt`). No label is drawn over another label, a similarity box or another node: in the overview the labels grow with the zoom, more slowly than the graph, and a label that has no free place appears when the zoom makes room for it, and in a result view it moves to another side of its node, away from its edges, or appears when its node is hovered. A click on a node gives its own label and the labels of its neighbours the first places, on the side away from it; a hover only highlights the neighbours and moves no label. Labels too small to read in a crowded view also wait for the zoom.
- `database-adapters.js`, `fifa2026-data.js`, `nobel-prize-data.js` and the two `.ttl` files: the built-in graphs. An uploaded Turtle file is parsed by `vendor/n3.v2.13.12.min.js` (N3.js, MIT license, `vendor/n3-LICENSE.txt`).
- `demo-data.js`: the recorded queries and the live defaults.
- `recorded-runs.js`: the recorded answers.
- `video/`: the narrated demo video.
