GenSPARQL · the GENOP operator

Open-world generation, closed-world validity — in one query

GENOP calls an LLM during SPARQL evaluation, binds what it generates to query variables, and joins those values back against the knowledge graph. The KG keeps the answers honest: generated values with no KG counterpart are dropped.

Data: 2026 FIFA World Cup KG (Wikidata, 913 entities). Model: Qwen3-30B-A3B-Instruct-2507, self-hosted (vLLM). Grounding θ = 0.85. Real run output.

SPARQL + GENOP

SELECT ?t WHERE {
  GENOP("List the national teams
        in the 2026 World Cup.",
        (?t),
        <model:openai:Qwen3-30B>)
  ?t a ex:Team .  # KG type
}

B · Hybrid — BGP + GENOP + join

Closed-world constraint (a group's teams) meets open-world generation (a star player), joined and validated against the KG squad.

SELECT DISTINCT ?team ?star WHERE {
  ?team ex:inGroup ?g ; rdfs:label ?team .  # KG
  ?g rdfs:label "Group A" .
  GENOP("a star player of {?team}",
        (?star), <model:…>)             # LLM
  ?p ex:playsFor ?team ; rdfs:label ?star . # ⨝ sim
}
South Korea→Son Heung-min
Mexico→Javier Hernández
Czechia→Tomáš Vaclík

Plain SPARQL has no “star player” triple → returns nothing. GENOP fills it; the sim-join validates each name against the real squad (accents recovered).

GenSPARQL extends SPARQL 1.1 on Apache Jena ARQ. KG built from Wikidata (Q5020214): 48 teams · 12 groups · 16 venues · 12 host cities · 825 squad players.
