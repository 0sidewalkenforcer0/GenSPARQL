**A generative extension of SPARQL 1.1 for Apache Jena: an LLM generates values during query evaluation, and a similarity join maps generated names to entities of the graph.**

▶ **[Try the workbench](https://0sidewalkenforcer0.github.io/GenSPARQL/)** on two graphs built from Wikidata, the 2026 World Cup and the Nobel laureates. Its recorded mode replays the answers of three open-weight LLMs, and its live mode runs your own queries, also over a Turtle graph that you upload, with a local model ([setup](#live-mode-with-a-local-model)). ▶ **[Watch the 3-minute video](https://0sidewalkenforcer0.github.io/GenSPARQL/video/gensparql-demo.mp4)**.

Knowledge graphs on the Web are incomplete, and SPARQL answers a query only from the stored triples. Large language models (LLMs) can predict missing facts, but an LLM returns names instead of IRIs and requires one call per binding of a query variable. GenSPARQL extends SPARQL 1.1 with an operator `GENOP` that binds values generated by an LLM to query variables during query evaluation. A similarity join maps generated names to entities of the graph, and the query planner invokes the LLM only for the bindings selected by the other graph patterns and filters. This repository holds the engine, the web workbench and the evaluation of the GenSPARQL demo paper.

## Quick Start

### Recorded mode

The [project page](https://0sidewalkenforcer0.github.io/GenSPARQL/) runs the recorded mode in the browser. For each graph it replays three queries of the paper with the answers that Qwen3-30B, Qwen3-8B and Mistral-7B gave in the evaluation, so it needs no model and no installation.

### Live mode with a local model

The live mode sends each query to the GenSPARQL service on this machine, which calls the LLM. It needs Java 17 or higher, Maven 3.8 or higher and [Ollama](https://ollama.com/):

```bash
git clone https://github.com/0sidewalkenforcer0/GenSPARQL.git
cd GenSPARQL
ollama pull mistral:7b               # once; Ollama serves on http://localhost:11434
ollama pull bge-large                # once, for the embedding similarity
./start-fuseki.sh                    # builds the modules and serves http://localhost:8080/
```

Open `http://localhost:8080/?mode=live`. The live panel is preset to Ollama on this machine: the endpoint `http://localhost:11434/v1`, the chat model `mistral:7b` and, for *Embedding (cosine)*, the embedding model `bge-large` at the same endpoint. The API key field can stay empty. Ollama serves a 4-bit build of Mistral-7B-Instruct-v0.3, so its answers can differ from the recorded ones. The prompts and the texts to embed go to Ollama on this machine and nowhere else. Any other OpenAI-compatible endpoint, such as a vLLM server or a hosted API, can be entered instead; its key is sent with each query and not stored. `http://localhost:8080/` opens the recorded mode.

The sample queries of the live panel follow the scenarios of the paper. *Load sample* also selects the graph that the sample queries. With Mistral-7B and the Jaccard similarity on a laptop:

| Sample | Scenario of the paper | LLM calls | Time |
|--------|----------------------|-----------|------|
| World Cup · positions of the Argentine players | 1, Figure 2(a) | 26 | 10 s |
| World Cup · players who have won a World Cup | 2, Figure 2(b) | 1 | 6 s |
| World Cup · national teams (vary θ) | 2 | 1 | 3 s |
| World Cup · defenders of Group A | 3 | 104 | 48 s |
| Nobel · fields of the prize (vary θ) | 2 | 1 | 1 s |
| Nobel · birth years of Physics laureates since 2020 | 1 | 17 | 7 s |
| Nobel · contributions of Physics laureates since 2020 | 3 | 17 | 11 s |
| Nobel · quantum mechanics pioneers | 4 | 1 | 1 s |

The samples can be edited, and the live panel also runs queries of your own and graphs uploaded as Turtle files. The [workbench README](docs/README.md) describes the two modes and the service API.

### The service

`./start-fuseki.sh 9090` serves on another port. The service answers only connections from this machine, because a query names the endpoint that the service sends its prompts to. To accept connections from the network, start it with `MAVEN_OPTS=-Dgensparql.server.allowRemote=true ./start-fuseki.sh`. The read-only Fuseki dataset is at `/gensparql`, and the workbench uses `GET /api/gensparql/health`, `POST /api/gensparql/datasets` and `POST /api/gensparql/query`. Clients other than the workbench can configure the LLM through the environment instead:

```bash
export OPENAI_BASE_URL=http://localhost:11434/v1   # or a vLLM server, or a hosted API
export OPENAI_API_KEY=...                          # only for a hosted API
./start-fuseki.sh
```

### Build and test

```bash
mvn -q compile    # also generates the parser from the JavaCC grammar; prints nothing on success
mvn -q test
```

## The GENOP Operator

`GENOP` is an element of group graph patterns, alongside `FILTER`, `BIND` and `OPTIONAL`:

```sparql
GENOP("<prompt, may contain {?var} placeholders>", (?out1, ..., ?outk), <model:PROVIDER:MODEL> [, θ])
```

A placeholder `{?x}` in the prompt refers to the query variable `?x`. A `GENOP` is in *context mode* if its prompt contains placeholders and in *base mode* otherwise. The optional `θ` in [0, 1] is the threshold of the similarity join of this `GENOP` (see the next section); without it, the default `θ0 = 0.85` applies. The engine asks the LLM for the generated tuples as a JSON array, so the prompt does not need to; an empty array means no answer. As in the paper, `GENOP` occurs only outside `EXISTS` and `NOT EXISTS`, and the parser rejects a `GENOP` inside them.

Both examples are the queries of Figure 2 of the paper and run as written over the World Cup graph `docs/worldcup2026.ttl`, here with Mistral-7B on a local Ollama server.

**Generating attributes (context mode).** The prompt contains a placeholder, so the LLM is called once for each solution of the other patterns, here for each of the 26 players of Argentina, and fills in a property that the graph does not store:

```sparql
PREFIX ex:   <http://example.org/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?name ?pos WHERE {
  ?player ex:playsFor ?t .
  ?t rdfs:label "Argentina" .
  ?player rdfs:label ?name .
  GENOP("Position of {?name}?", (?pos), <model:openai:mistral:7b>)
}
```

**Listing entities (base mode).** The prompt has no placeholder, so a single LLM call returns a list of names, and the similarity join maps them to the athletes of the graph. Names of players outside the 2026 squads, such as Pelé, map to no entity:

```sparql
PREFIX ex:   <http://example.org/>
SELECT ?player WHERE {
  ?player a ex:Athlete .
  GENOP("List footballers who have won the World Cup.", (?player), <model:openai:mistral:7b>, 0.85)
}
```

### Order of evaluation

Because `GENOP` lives in the query algebra, the planner places it after the patterns that constrain its inputs, so the LLM runs only on the bindings that survive. Within a group with the `GENOP` expressions G1, ..., Gn in written order, the planner orders the elements as follows:

- An `OPTIONAL`, `MINUS` or `BIND` is *deferred* if it mentions an output variable of a `GENOP`, or a variable of an earlier element that mentions one or is deferred itself.
- The other elements that mention no output variable come first. The filters over the variables that their triple patterns bind follow them, so they remove solutions before any prompt is sent.
- Then each Gi in written order, followed by the elements for which Gi is the last `GENOP` whose output variable they mention. These elements are joined with Gi by similarity (see the next section).
- Then the deferred elements, in written order, and finally the other filters.

An `OPTIONAL` or `BIND` that is not deferred comes before the `GENOP` expressions even when it is written after them, so it can bind a placeholder variable. A context-mode `GENOP` in the optional part of `A OPTIONAL { B }` can use variables of `A` in its placeholders. GenSPARQL therefore evaluates `B` separately for each solution of `A`, and keeps the solution unextended if `B` yields none.

## Mapping Generated Names to Entities (Similarity Join)

A generated value is free text, whereas a KG term is an IRI or typed literal, so the two cannot be joined by equality. When a `GENOP` shares an output variable with a graph pattern of its group, GenSPARQL joins them by **similarity** instead, in both modes:

- **What is compared.** Each generated value is compared with the labels of the term that the pattern binds: the values of the first of `rdfs:label`, `skos:prefLabel`, `schema:name` and `foaf:name` that the term has in the queried graph, or else its local name, and for a literal its lexical form. A match is kept when the similarity reaches the threshold `θ`, and the joined solution keeps the term of the graph.
- **Which variables.** A shared variable is compared by similarity if the `GENOP` side binds it to a generated literal, the output of an earlier `GENOP` that no pattern has mapped included, and by equality otherwise, for example an output that a pattern has already mapped to an entity. All of them use the threshold of the current `GENOP`.
- **Similarity.** The request chooses the Jaccard similarity of the lowercase word sets or the cosine similarity of text embeddings. If the embedding model fails, the query falls back to the Jaccard similarity, logs a warning and reports the fallback in the trace of the HTTP service.
- **Threshold.** The default θ0 is 0.85. It is an engine parameter, which `MAVEN_OPTS=-Dgensparql.theta0=0.9 ./start-fuseki.sh` sets for the service and `GenSPARQL.setSimilarityThreshold(0.9)` sets in Java. The fourth argument of a `GENOP` sets another value for that `GENOP`.
- **Modes.** The mode only decides how often the prompt is sent: a context-mode `GENOP` sends it once for every solution of the patterns that bind its placeholders, a base-mode `GENOP` once.
- **Where.** The similarity join also applies inside `UNION`, `OPTIONAL` and `GRAPH`, where it reads the labels of the named graph.
- **Filters.** For a literal `?x` that a `GENOP` with the threshold `θ` generated, `FILTER(?x = t)` holds if the similarity of `?x` to a label of `t` reaches `θ`, and `FILTER(?x != t)` is its negation. If two `GENOP` expressions generate `?x`, the threshold of the first of them in written order applies, since the solution keeps its value. All other expressions follow SPARQL.

Every entity that the similarity join maps a name to belongs to the graph, but the mapping can be wrong: a name, also one that denotes no entity of the graph, can reach the threshold for an entity with a similar label. In the evaluation, the embedding similarity made one such match at `θ = 0.85` (George P. Smith to George E. Smith) and none at `θ = 0.9`. Generated attribute values are literals that are not mapped, and they are only as reliable as the LLM that generated them.

## Evaluation

The evaluation runs on the two graphs of the workbench, built from Wikidata: the 2026 FIFA World Cup (1,248 players, 48 teams, 16 host cities and their stadiums; 4,000 triples) and the Nobel laureates (1,018 laureates, 1,026 awards; 10,849 triples). Three open-weight LLMs, Qwen3-30B-A3B-Instruct-2507, Qwen3-8B in non-thinking mode and Mistral-7B-Instruct-v0.3, were served by vLLM at temperature 0, and every answer went through `GENOP` in the HTTP service. The embedding similarity used bge-large-en-v1.5.

- **Generating attributes.** The generated positions are correct for 55-59% of the answered players (answering midfielder for every player: 33%; a uniform guess among the four positions: 26%), and the birth years for 69-90% of the answered laureates.
- **Mapping names to entities.** Over six list queries, 20-61% of the generated names denote no entity of the graph. At `θ = 0.85`, the embedding similarity (bge-large-en-v1.5) maps 83% of the entities that the names denote, with one wrong match; the Jaccard similarity maps 67%, with no incorrect match from `θ = 0.6` on.
- **Counting LLM calls.** The planner reduces the calls of a composed query from 1,248 to 104, and those of a second one from 230 to 17.

[`eval/www27/README.md`](eval/www27/README.md) describes how to rerun the evaluation; `eval/www27/results/` holds the queries' results, the recorded LLM answers and the scores, and `eval/www27/gold/` the gold data.

## Data and Privacy

- The two graphs in `docs/` are built from Wikidata (CC0) by `gensparql-example/data/build_worldcup2026_kg.py` and `gensparql-example/data/build_nobel_prize_kg.py`. The World Cup graph holds the official 2026 squads as Wikidata records them, and the Nobel graph includes the citizenship and gender of the laureates.
- Generated values about people can be incorrect or biased. GenSPARQL does not write them into the graphs: the dataset of the service is read-only.
- The workbench collects no user data. Names of people in prompts and embedding requests reach an external server only when a remote endpoint is chosen; with the default settings they go to Ollama on this machine. The page loads one web font from Google Fonts.

## Known Limitations

- The HTTP service answers `SELECT` and `ASK` queries. `CONSTRUCT` and `DESCRIBE` queries run through the [Java API](#using-gensparql-from-java).
- A context-mode `GENOP` sends one prompt per solution of the patterns that bind its placeholders, also when several solutions yield the same prompt. A query that asks about the team of each of the 1,248 players prompts 1,248 times; a sub-select of the distinct team names first prompts 48 times.
- `GENOP` cannot occur inside `SERVICE`, since the remote endpoint would have to evaluate it. The parser rejects such a query.

## Using GenSPARQL from Java

### Java API

```java
GenSPARQL.init();                                  // register engine + functions
Query q = GenSPARQLQueryFactory.create(queryString);
Context cxt = ARQ.getContext().copy();
cxt.set(GenSPARQLConstants.SIM_TEXT, new JaccardSimText());
try (QueryExecution qe = GenSPARQL.createQueryExecution(q, dataset, cxt)) {
    ResultSet rs = qe.execSelect();
    // ...
}
```

The context chooses the similarity of the similarity join: `JaccardSimText`, or the cosine of embeddings with

```java
LLMProvider ollama = new OpenAIProvider("", "http://localhost:11434/v1", "", "http://localhost:11434/v1");
cxt.set(GenSPARQLConstants.SIM_TEXT,
        new EmbeddingSimText(new JaccardSimText(), ollama, ModelSpec.fromURI("model:openai:bge-large")));
```

Without this setting, the engine uses the embeddings of the default provider. Jena's own `QueryExecutionFactory` also reaches GenSPARQL after `GenSPARQL.init()`. GenSPARQL is not yet published to Maven Central; [RELEASING.md](RELEASING.md) describes how releases will be made.

### LLM providers and models

The model is named in the query as `<model:PROVIDER:MODEL>`:

| Provider | Model reference | Environment variable |
|----------|-----------------|----------------------|
| [Ollama](https://ollama.com/) (local, OpenAI-compatible) | `<model:openai:mistral:7b>` | `OPENAI_BASE_URL=http://localhost:11434/v1` (no key needed) |
| Self-hosted [vLLM](https://docs.vllm.ai/) (OpenAI-compatible) | `<model:openai:Qwen/Qwen3-30B-A3B-Instruct-2507>` | `OPENAI_BASE_URL` |
| OpenAI | `<model:openai:gpt-4o>` | `OPENAI_API_KEY` |
| [OpenRouter](https://openrouter.ai/) | `<model:openrouter:deepseek/deepseek-chat>` | `OPENROUTER_API_KEY` |
| Anthropic | `<model:anthropic:claude-...>` | `ANTHROPIC_API_KEY` |
| Mock (no network) | `<model:mock:...>` | none |

In the workbench, `<model>` stands for the model of the live panel. Every provider asks the model for a JSON array and reads the values of every array in the answer. [`deploy/README.md`](deploy/README.md) describes how to serve the chat and embedding models with vLLM on a SLURM cluster, and `OPENAI_EMBEDDING_BASE_URL` and `OPENAI_EMBEDDING_MODEL` select the embedding model of the default provider.

### Example programs

`gensparql-example/` holds Java example programs for the base and context modes, `UNION`, `OPTIONAL` and the similarity join over a small graph of scientists and awards and an earlier build of the Nobel graph (`gensparql-example/queries/`, `gensparql-example/data/`). `./run_query1.sh` runs plain SPARQL without an LLM. The other scripts call `<model:openrouter:openai/gpt-4o-mini>` through [OpenRouter](https://openrouter.ai/) and stop with a message if `OPENROUTER_API_KEY` is not set:

```bash
cd gensparql-example
./run_query1.sh
export OPENROUTER_API_KEY="sk-or-..."
./run_query2.sh          # context-mode GENOP
```

The module `gensparql-functions` also registers auxiliary `gen:*` SPARQL functions, which the paper does not use; [its README](gensparql-functions/README.md) lists them.

## Troubleshooting

**"Java version not supported."** Install Java 17 or higher and make it the default, for example `brew install --cask temurin@17` on macOS or `sudo apt install openjdk-17-jdk` on Ubuntu; `java -version` should show 17 or higher.

**Missing or invalid API key.** A hosted API needs its key exported in the shell (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY` or `OPENROUTER_API_KEY`). A local OpenAI-compatible server such as Ollama or vLLM needs only `OPENAI_BASE_URL`, and no key. To try GenSPARQL without a provider account, use the workbench with Ollama (see [Quick Start](#quick-start)), the `mock` provider, or `run_query1.sh`.
